## 本轮完成

新增 `scripts/audit-agent-quality.py`，离线读取真实模型评测的 manifest 与逐轮记录，不再调用模型。将执行失败、自动契约失败、空回答及受控的证据核查错误提示作为异常信号单列，不能把信号缺失解释成答案正确。

按组输出回答正确性、任务完成度、补问适当性的人工标注覆盖率、已标注通过率，以及全量标注后才允许计算的完整样本通过率。任何未标注项均为 null，不算正确。未知或重复轮次、非布尔标签、缺少评审来源均拒绝；评审文件同时绑定原始 manifest 和 trace 的 SHA-256，防止误用其他实验的标签。评审身份仅为文件声明，未实现身份认证或双人一致性检查。

原始实验不修改，每次审计创建独立 quality 目录。`review-template.json` 填写后通过 `--reviews` 输入再生成报告；旧版 `review.jsonl` 不直接作为新版输入。

```powershell
# 在含项目 Python 依赖的环境中运行；本次使用现有 Agent Docker 镜像验证。
python scripts/audit-agent-quality.py evaluation/runs/agent/20260915T093918Z_2704440f
python scripts/audit-agent-quality.py <原始实验目录> --reviews <已填写的review-template.json>
```

标注时查阅原始场景、同场景前序轮次、工具结果和回答：

- answer_correct：回答中的事实与实际返回数据是否一致；没有回答用户问题时不能仅因未编造就判正确。
- task_fulfilled：是否完成本轮请求，例如复述更正后的使用情况、核实指定订单或明确指出无法确定。
- appropriate_clarification：补问或不补问的选择是否合理；已提供的信息是否被重复索要。未能评审则保留 null。
- notes：记录支持判定的事实、失败原因。机器辅助意见不能填写为 human 盲审结论。

本轮八项评测及质量审计测试通过。对 P3g 原始运行完成离线审计，产物为 `evaluation/runs/agent/20260915T093918Z_2704440f/quality_20260915T094708Z_7c0face4/`。人工评分仍待填写；没有追加付费调用，也没有修饰原有实验结果。

## 达到可交付 v1.0 的五个剩余工作包

不按代码行数或已装中间件数量估算完成百分比。现状是可运行、已有工程约束的开发原型；没有生产流量和故障证据，不能称为生产级。

1. **AI 质量闭环**：补齐人工评审，扩充并按场景族隔离开发/测试数据，冻结后重复真实模型实验；接真实已发布政策检索验证引用与撤回；完成原规划的受控网络搜索，或明确记录尚未验收。预算和样本规模分批递增，不以“凑足题数”替代标注质量。
2. **可靠异步业务（P4 优先）**：审核产生退款任务与 Outbox 同事务落库，RabbitMQ 投递，模拟渠道 worker 幂等处理，明确 REFUNDING/REFUNDED/FAILED 或待核实状态、重试与对账。验收重复消息、确认后响应丢失、消费者重启与并发审核；不能把模拟渠道写成真实支付平台接入。
3. **并发与缓存性能**：先复现客服抢单、重复提交、热点查询与会话限流；采集数据库基线和慢 SQL。再为测得的热点加入 Redis 缓存，设计 TTL、失效和降级；权限与政策版本必须进入缓存设计。验收不同并发档位的吞吐、P95、错误率、连接池和数据库压力，给出明确硬件与数据规模。
4. **运行与恢复**：结构化日志贯通 run/operation/order，指标与告警；超时、取消、队列积压、依赖故障、备份恢复与干净部署验证。当前 SQLite 单实例边界必须如实保留；若需要多实例，应先设计共享持久状态和 worker 租约，不能只加 Redis 锁就声称支持横向扩容。
5. **交付与学习验收**：三侧业务和 Agent 接管交互整理、错误和空态、独立环境启动、实际试用反馈、公开素材/许可证审查、贡献矩阵及故障/性能报告。学习同步进行，需能独立解释事务边界、锁冲突、缓存失效、事件重放和评测分母。

## 锁与缓存的取舍

退款正确性首先依赖数据库事务、唯一约束、条件状态迁移和渠道幂等键。单条领取可用条件 UPDATE；订单和审核读取修改可用行锁。Redis 分布式锁适用于确有跨进程协调需求的工作，需处理租约超时、进程暂停、所有权与旧持有者写入；不是给每个接口加锁。

缓存应服务于可测量的热点，例如公开商品详情或带发布版本的政策读取。对订单支付状态、权限、退款状态必须有更严格的权威回读和失效约束。还没有性能基线时，优先做并发正确性和测量，不先堆复杂多级缓存。

建议接下来优先推进可靠异步退款与并发正确性；人工质量标注和 AI 评测作为持续质量门槛并行推进。这里的“并行”是工作流安排，不代表本轮创建多 Agent 或自动运行新的付费实验。
