# P3f 多轮 Agent 对照评测

## 本轮交付与评测边界

新增八个合成开发场景、十八轮输入，涵盖订单指代、切换订单、更正订单、使用事实更正、缺少订单补问、售后预览确认、无政策拒绝保证、任务重置。场景在 `evaluation/agent-multiturn-v1.json`，未经独立人工留出集验收；不能称为行业基准或独立测试集。

评测调用真实 `runtime.execute`、LangGraph 循环、上下文构建器、短期状态与 SQLite 存储。每个场景、每次重复、每个对照组使用独立会话。业务工具全部由评测进程替换为合成工具，不访问现有 Java、MySQL 或 Milvus，不提交真实业务。政策检索故意返回空证据，用于检查缺依据场景；这不是 RAG 召回/精排评测的替代品。

两个对照组采用相同历史窗口和 12000 字符预算：history 关闭任务数据、任务工具与相应提示；task 保留当前 P3e 行为。开关仅为内部 Python 参数，HTTP 不开放。对照比较的是整套上下文机制，不能将差异归因于单一字段或单一提示词。

## 运行方式

默认只运行脚本引擎，**无模型费用**，不需要真实业务账号或密钥：

```powershell
./scripts/evaluate-agent.ps1
```

脚本引擎只做简单订单识别，故意不具备完整语义理解或售后能力。它不读取期望标签，正常会留下失败场景。默认退出码 0 表示实验完成，绝不代表所有场景正确；加 `-RequirePass` 会在契约失败时返回失败，适合 CI 门禁。发生中途错误时保存已完成记录，manifest 标为 incomplete，退出失败，不能作为完整实验比较。

真实模型模式必须显式指定 `-Live`。准备专用的、已忽略的 `.local/agent-eval.env`，只填写所选服务商的 `ASTER_DEEPSEEK_MODEL`、`ASTER_DEEPSEEK_API_KEY`，可选 `ASTER_DEEPSEEK_BASE_URL`；其他服务商对应 OPENAI、KIMI、CUSTOM 前缀。不要复制整个项目环境文件，不要把密钥写进命令、报告或聊天。此模式不读取当前个人账号数据库中的模型密钥。

```powershell
# 仅在明确允许产生 API 用量、准备好独立配置后运行。
./scripts/evaluate-agent.ps1 -Live -Provider deepseek -Repeats 3 -MaxModelCalls 300
```

最大模型调用数含外层循环和政策证据判断。耗尽则停止后续调用；不是人民币费用上限。每次模型输出长度与单轮工具/时间预算沿用网关和运行时。采样参数沿用服务商默认值并在 manifest 声明，未固定随机种子或温度；一次运行差异不能视作稳定改进。建议重复运行并人工检查失败样本。

## 产物和指标

每次创建唯一的 `evaluation/runs/agent/<UTC时间>_<随机ID>/`，不覆盖之前的实验，目录已被 Git 忽略：

| 文件 | 内容 |
| --- | --- |
| manifest.json | 模式、模型标识、语料 SHA-256、运行时代码与依赖锁哈希、Python 版本、重复次数、调用预算、实验完成状态 |
| turns.jsonl | 每轮自动检查、工具名与订单 ID、终态、耗时、用量、待人工复核的最终回答 |
| summary.json | 分组通过数与分母、场景契约通过数、P50/P95、未报告用量轮数 |
| report.md | 可阅读对照报告，明确标注验证类型 |
| review.jsonl | 人工复核模板；正确性与补问适当性初始为 null |
| sessions.sqlite | 本次独立合成会话，便于本机排查，不作为公开产物 |

自动检查包括执行是否正常结束、要求查询的订单是否全部正确、是否出现未请求的预览、请求预览后是否等待确认。查错后再查对仍失败。场景内所有轮次都完成且全部契约通过才算场景契约成功，失败轮次保留在分母中。不同指标只统计适用轮次；缺失服务商 token 用量单独计数，不能把记录的总和当作完整成本。P95 是本机合成工具环境端到端耗时，脚本模式耗时不代表真实模型性能。

**场景契约通过率不是回答准确率或业务任务完成率。** 使用事实是否正确、更正是否理解、补问是否必要、拒答是否适当，都需要人工对照原始场景和实际回答复核。当前 review 文件是待填写模板，尚未实现人工标注汇总或双人一致性统计；不能把未填写条目当作正确。

复现应比对 manifest 的语料和源码哈希，而不是只比文件名。逐轮回答和数据库留在本机；公开简历配套报告前应复核并仅发布必要摘要。本轮不运行付费模型，不报告模型质量提升。

## 简历表述

目前可以如实描述：实现多轮 Agent 对照评测管线，覆盖八类开发场景；支持历史窗口与结构化任务状态对照、逐轮契约检查、调用预算、失败留存、源码/数据版本追踪与人工复核模板。

不能写“准确率提升 X%”“避免所有串单”或“生产级评测体系”。后续应先扩充并人工审核场景，按场景族划分独立留出集，运行真实模型，再汇总人工标注和成对差异，最后选择有证据支持的数字。
