# P3g 首轮真实模型多轮评测

> 验证记录：结果与限制对应文中列明的运行日期及配置。当前使用方式见[工程文档](../README.md)，不同实验结果不合并为统一准确率。

## 授权与运行范围

用户在本轮明确要求开始接入真实模型评测，恢复此前暂停的真实调用。首轮复用其已保存的 DeepSeek 连接，模型标识为 `deepseek-flash`，八个开发场景、两组各十八轮、一次重复，最多一百次模型调用。没有修改运行中的业务服务，也没有提交真实订单或售后。

新增 `evaluate-agent.ps1 -Live -SavedMember <本机账户编号>` 选项，通过只读挂载访问指定账户、指定服务商的加密连接，仅在进程内解密，不创建明文密钥文件。数据库以 `mode=ro` 打开，不能调用生产 Store 初始化，以免触发执行恢复逻辑。模型请求沿用 public-only 出站检查。默认不指定 SavedMember 时仍使用独立 `.local/agent-eval.env`。这是一项本机部署管理员脚本能力，不是对普通用户开放的跨账户 HTTP 接口。

五项评测计分与配置测试通过，包含只读连接和密文账户绑定验证。合成业务工具、开发场景、一次重复、服务商默认采样的限制仍然适用。没有调用真实在线 Milvus 检索，本轮不能视为完整线上 RAG 答案评测。

## 报告解读与已发现问题

首轮已完整结束：82 次实际模型调用，服务商报告用量共 117065 token，没有缺失用量的轮次。未根据未经核实的价格估算费用。

| 指标 | 仅历史对话 | 历史＋任务状态 |
| --- | ---: | ---: |
| 自动场景契约通过 | 7/8（87.5%） | 8/8（100%） |
| 订单选择检查 | 10/11（90.91%） | 11/11（100%） |
| 无未请求预览 | 17/17 | 17/17 |
| 请求预览后等待确认 | 1/1 | 1/1 |

| P50 端到端耗时 | 2.868 秒 | 4.789 秒 |
| P95 端到端耗时 | 13.000 秒 | 10.370 秒 |
| 报告 token | 41916 | 75149 |

任务组自动场景通过率高 12.5 个百分点，但 token 用量约增加 79.3%。每组只有十八轮，P95 对单个慢请求很敏感；不能据此认定任务组更快。一次小样本结果没有统计显著性检验，不是独立盲测，也不能认定整体回答准确率为 100%。

历史组自动失败位于 `order-switch` 第三轮：用户切换到订单 202 后询问“刚才那一单”，模型查询了 202 和旧订单 101，并称指代不确定；任务组只查询 202。这是多查了不必要的订单，并非发生了错误退款或越权访问。

本轮原始输出位于忽略目录 `evaluation/runs/agent/20260915T093918Z_2704440f/`。manifest、逐轮回答和用量用于追溯；当前轮次的自动契约并未覆盖回答语义正确性。

助手对已生成文本的定性检查发现：`usage-correction` 的 history 组第二轮，在用户要求复述“拆封了但没使用”时返回了“未能完成政策证据核查”的提示；task 组对应回答复述了更正后的使用情况。前者仍可能通过“正常结束、无误发预览”这两个自动检查。这是自动评分覆盖不足的实例，不能把自动场景通过率直接当作任务成功率。

上述检查由开发助手完成，不是人工盲审、独立评审或统计显著的收益证据。review.jsonl 继续保留待人工复核状态。后续应补充“完成用户要求的复述”“错误触发政策检索”“核查失败”标签，并在独立场景、重复运行上比较效果和用量；不得在看过本轮结果后修改题目再称为原始留出结果。
