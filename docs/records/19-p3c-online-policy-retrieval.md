# P3c 在线政策混合检索

> 验证记录：结果与限制对应文中列明的运行日期及配置。当前使用方式见[工程文档](../README.md)，不同实验结果不合并为统一准确率。

## 已实现的链路

MySQL 政策发布/修订/撤回事务 → 版本 epoch 与索引任务同事务写入 → 单消费者构建 Milvus 正式代际索引 → MCP 校验当前目录 → BM25 + Dense → RRF → CrossEncoder 精排 → 返回当前目录中的有效证据 → 回答前再次校验原文版本与哈希。

在线索引从 Java 鉴权目录读取，**不使用离线草案或评测集合**。本次最终正式索引包含 241 条客户条款（本批 240 条与既有 1 条），不含 16 份内部规范。Milvus 使用模型维度的 COSINE/FLAT 索引；模型提交与 P3b 配置一致，CPU 推理，候选各 20，RRF 常数 60，融合取 20 精排后返回 5。

## 事务、同步与切换

迁移 `006-p3c-index-outbox.sql` 创建 `aster_policy_index_job`。发布/撤回在事务内递增 epoch 并写入 PENDING 任务；事务失败不产生新索引事件。初始化迁移为当前 epoch 建立任务，不改变政策内容。

消费者每两秒检查当前有效目录，分页及结束时核对 epoch；同时对政策 ID、版本、条款号、标题、内容哈希构建稳定目录摘要。连续变更合并为最新快照，成功后旧任务标记 SUPERSEDED。失败写 RETRY，记录尝试次数，按上限 30 秒的退避重试。

集合名绑定模型配置、epoch、目录摘要；稳定主键 upsert 使部分构建可重试，不重复增加条款。重启可加载已经构建完成的同代集合；条目数不完整则重新 upsert。构建、flush、load、条目数及当前 epoch 核对完成后，才在进程锁内切换活动代际。数据库保存完成记录；服务重启前不会把该记录直接当作已加载完成。

正式服务只管理专用 `aster_live_*` 集合，切换后清理旧正式集合，不处理 `aster_eval_*`。锁内进行搜索或构建，繁忙时快速拒绝请求以便 MCP 降级。当前只允许一个消费者进程；**没有多实例 lease/fencing，也未实现增量向量更新**，每个新代际仍是完整客户快照。大库需要后续优化。

## 不使用失效条款的门槛

1. Java 目录先过滤草稿、内部、撤回、旧版本和无效日期。
2. MCP 每次从权威目录构建快照，向检索服务发送 epoch 与摘要；服务活动索引不匹配时拒绝 Hybrid。
3. 服务只返回证据 ID；MCP 从刚读取的权威目录还原正文，拒绝未知或重复 ID，不直接信任向量服务返回的正文。
4. 检索结束再次核对 epoch，变化则要求重新查询；最终回答前保留现有原文与哈希校验。

目录摘要还涵盖时间条件导致的可见集合变化，不能只因 epoch 相同就复用旧集合。模型引用的语义支持仍需独立评测；此机制不意味着每句话都被证据支持，也不能追溯撤销已送达的历史回答。

## 降级、配置与鉴权

MCP 调用检索服务的超时预算为 2.5 秒。索引未就绪、代际过旧、繁忙、服务失败或候选非法时，使用本次读取的有效目录执行 BM25，并记录 `degraded=true`、method=BM25 及原因。正常混合结果标记 HYBRID_RRF_RERANK。页面执行过程显示方式、证据数与耗时，降级提示在折叠区域外显示。

部署配置 `ASTER_RETRIEVAL_MODE` 默认 hybrid，设为 bm25 可明确回到基线；切换配置后重新启动 MCP。没有用 fixture 或模型生成伪装检索结果。

消费者与 Java、MCP 与消费者使用本地随机服务密钥，保存在忽略目录 `.local/policy-index.key`，以只读文件挂载，不放进聊天、日志或仓库。索引接口只提供客户政策目录、任务状态及结果上报，不提供订单或管理操作。密钥以常量时间比较验证，匿名请求被拒绝。

服务仅运行在本地 Docker 网络，无检索 HTTP 主机端口。它是本地单实例架构，尚无生产级限流、多实例容错或管理控制台；健康检查表示进程存活，业务就绪应读取鉴权 `/status` 的 ready 字段。

## 启停与验收

前置条件：已完成 P3b 的检索镜像构建与固定模型缓存准备。`scripts/start-p2.ps1` 应用迁移、启动 Milvus，并加入 `compose.p3c.yml` 的消费者。`scripts/stop-p0.ps1` 停止完整服务，保留数据卷及密钥。模型权重只从已有固定缓存加载，缺失时报告 RETRY，不暗中切换模型。

`scripts/verify-p3c.ps1` 验证生命周期及真实 Milvus 停机/恢复，会短暂影响 Hybrid，必须独立顺序运行；finally 恢复 Milvus。`scripts/verify-p2.ps1` 运行原有回归并恢复正常模型模式。不要并发运行两套会改动服务或政策的验收脚本。

本轮已验证：

- Java 构建成功，12 项原有定向业务测试通过。
- 前端类型检查与生产构建通过。
- 混合检索与引用定向测试 8 项通过，覆盖超时、未知 ID、检索中版本变化与原文校验。
- 当前源码完整 Python/MCP 测试 55 项通过、3 项按条件跳过（真实模型与两项需显式启用的 P3c 专项）；P3c 专项另行执行，结果见下项。
- 真实索引生命周期与可用性 2 项通过；真实 Milvus 停机降级与恢复各 1 项通过。
- 原回归 11 个浏览器场景、17 项 API smoke 及退款审计一致性通过。
- 发布失败不增加 epoch；修订后旧版与内部资料不返回；撤回后即使等待索引更新，也不会返回被撤回条款。测试创建的政策在 finally 撤回。

首次构建发现 Java 成功响应可能省略空 data 字段，消费者误判失败；修复后重跑通过。本轮无真实模型调用，浏览器生成使用显式 fixture，结束恢复正常模式。

本次验收期间两套脚本存在部分时间重叠，结果均通过；后续复现明确要求顺序运行，避免故障注入与其他任务互相干扰。耗时不是独立压测结论。
