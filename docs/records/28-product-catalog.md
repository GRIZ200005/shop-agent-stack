# 原创生活商品目录 v1

> 验证记录：结果与限制对应文中列明的运行日期及配置。当前使用方式见[工程文档](../README.md)，不同实验结果不合并为统一准确率。

本轮为客户侧新增 100 件可购买的合成商品，每件一个标准 SKU、一张独立 AI 生成图片。10 个分类各 10 件：杯壶饮具、餐厨器皿、收纳整理、家纺织物、文具办公、数码配件、通勤出行、运动户外、家居日用、阳台园艺。

名称、价格、材质、规格、使用说明和养护注意事项逐项编写在 `catalog/products.tsv`。价格为模拟定价；销量与评论数不造假，初始销量为 0，不承诺认证、实测功能或真实发货。页面详情明确说明合成商品与 AI 示意图性质。

## 数据与图片

新增品牌为 Aster Studio，品牌 ID 101，分类 ID 1011–1020，商品和 SKU ID 10001–10100。保留原有商品和历史订单，不覆盖其名称、库存和图片。编号是系统内部关联键，用户看到正式商品名称。

所有新图片使用内置 image_gen 分别生成，不使用外部商家照片。发布资源位于 `apps/web/public/products/catalog-v1/`。生成原图经 WebP 编码缩小到最长边 800 像素，保留本机 PNG 原图；未修改产品外观。`catalog/image-manifest.json` 记录每张图片的完整提示词、源文件哈希、发布文件哈希与尺寸，不记录个人目录路径。

配图用途是商品示意，不能据图推断额外配件、材料等级、检测报告或未记载的功能。

## 复现导入

```powershell
# 只校验文字目录并生成待审 SQL，不写数据库
node scripts/import-product-catalog.mjs
# 在本地 Docker 环境导入，需已存在全部发布图片
node scripts/import-product-catalog.mjs --apply
```

导入是本地初始化工具，不是面向用户开放的管理 API。使用现有环境变量连接本机数据库，不输出凭据。业务表写入在同一事务内完成，SQL 字符串通过 UTF-8 十六进制编码，字段经过格式检查；命名锁防止两份本工具同时导入。所有保留编号先检查冲突，不兼容记录使事务失败。相同目录再次运行会跳过已存在记录，不重置已售库存、锁定库存与销量。

后续修改已上架商品应走明确的商品管理流程；本脚本不替代更新接口，也不提供删除历史交易数据的回滚命令。本机审阅 SQL 和导入 manifest 在 `.local/catalog/`，不入库。

图片重打包工具 `node scripts/prepare-catalog-images.mjs` 需要本机 Edge 和已安装的前端 Playwright；仅在重建素材时使用，日常导入无需再次生成图片或调用模型。

## 页面与查询改动

客户页支持 20 件一页、分类筛选、名称关键词搜索、价格排序和商品详情。计数使用服务端总数，不再只显示第一页数量。详情展示可售 SKU 库存、材质规格、使用注意事项与合成说明。购物袋和订单使用商品图片快照，新商品不再落到通用音箱占位图。

mall 商品搜索沿用原有名称 LIKE 匹配。默认排序增加 sort、id，同价排序增加 id，固定同一数据集的分页顺序；本轮没有实现语义商品检索。

## 验证与评测边界

`apps/web/tests/catalog.spec.ts` 检查全量商品分页、SKU、100 张图片哈希、10 个分类、6 组人工编写的关键词结果，以及客户页详情、购物袋图片和移动端宽度。`catalog/search-cases.json` 另有 20 个待接入 Agent 的购物问答场景，包括预算、尺寸兼容、无结果和禁止虚构功能等情形。

这些是目录功能验收与后续 Agent 评测素材，不是已经完成的商品 RAG 准确率。新增商品不会自动进入政策向量索引；商品价格、库存与规格应通过业务工具读取，政策 RAG 仍使用已发布政策。后续要增加商品查询工具和证据判定，才能测商品推荐/问答的真实模型表现。

100 件商品有助于演示和功能覆盖，不能代替万级、十万级性能数据；前一轮 4 商品性能报告是历史结果，不能与本目录上线后结果混用。

实际执行结果见本文件末尾验收记录，未执行的未来场景不计入通过率。
