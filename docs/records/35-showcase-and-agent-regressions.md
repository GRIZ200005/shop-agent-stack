# 三侧使用验证与 Agent 回归

日期：2026-09-16。[产品图集](../showcase.md) · [测试说明](../testing.md)

本记录覆盖本机浏览器操作、维护者提供的截图和针对缺陷的回归。截图证明对应页面的可见结果，不作为整体答案准确率或生产容量指标。

## 三侧业务操作

浏览器实际执行过客户注册、商品详情查询、将一件商品加入购物袋、创建订单与 59 元模拟支付；管理员记录模拟发货和派送，客户确认收货；另有客户提交咨询、客服领取回复并标记解决。使用合成身份与虚拟地址，无真实支付或配送。

维护者随后提供另一笔同金额订单的连续截图：已模拟发货、派送、确认收货、售后领取、填写审核说明、客服与客户两侧的模拟退款完成。政策管理截图显示正式标题、已发布版本与条款索引就绪。

客户与管理员曾对同一订单显示相差 8 小时的时间。修复将不带偏移的后端 UTC 时间统一解析；覆盖带偏移、不带偏移、小数秒和非法日期的本地回归通过，刷新后两侧时间一致。

## 政策核查故障与修复

最初两次请求均成功走到混合检索，返回 5 条政策，但核查阶段产生 `invalid_assessment`。原事件缺少终止原因与具体校验项，不能确定原始错误属于截断还是格式问题。

适配修复包括：接受单个 JSON 代码块、校验 JSON 对象与字段、记录提供商终止原因、提高核查输出上限至 4,096 token，并保留总执行预算。脱敏事件记录响应长度和校验类别，不保存原始思考内容。

授权的三次诊断调用使用重建的模拟提问与公开合成条款，均正常结束并返回合法判断，合计 2,963 reported tokens；没有复现原始失败。该结果不是原请求的完整重放，也不构成端到端效果评测。

后续运行揭示另一处问题：模型同轮发起两条政策搜索，第一条被判充分，第二条单独核查丢失第一条证据，并因补查预算耗尽而停止。修复为同轮检索先合并去重再统一核查，同时保留当前运行此前接受的证据、两次搜索上限与最终来源复核。

最终维护者截图展示到货破损规则回答、申请信息、审核方及三张条款来源卡片，回答明确未核实订单状态且未创建申请。这是一条成功的用户操作样本，不替代独立题集评测。
