# P3e 多轮任务状态与上下文管理

> 验证记录：结果与限制对应文中列明的运行日期及配置。当前使用方式见[工程文档](../README.md)，不同实验结果不合并为统一准确率。

## 实现范围

在现有 LangGraph 工具循环中加入本地 `update_task_context` 工具，维护当前会话的结构化短期记忆。不是长期用户画像，不导入私人参考项目，也不新增模型服务依赖。

状态包括：订单原文指代、商品型号、使用情况、售后原因、时间、待补问字段和过去成功查询的订单 ID。每条用户事实保存当前输入中的原文片段及来源 run ID，并标记 `user_claim`。服务端拒绝非原文值和授权、退款结果等未知字段。字段分类、重置意图与事实选择仍依赖模型，原文校验不证明语义理解正确。

更正覆盖同一字段。更新不同的订单指代或成功读取不同订单时，保守清空旧字段；同一订单的不同文字表达也可能触发清空，宁可重新补问。模糊的“最近那一单”仍需要模型调用业务工具解析，不能据此宣称已经解决所有指代问题。

政策检查器接收最新任务状态；缺少事实时保存待补问字段，下轮仍可读取。用户补充字段后移除对应待补问项，但检查器仍有权再次询问。记忆不保存政策正文、订单金额、付款状态或确认凭据，它们不能成为业务事实缓存或授权依据。

## 持久化与边界

SQLite 新增 `task_context` 表，以 session ID 隔离，访问时检查账户所有权。状态与本轮完成/等待确认状态在同一事务保存；失败、停止的本轮更新不写入持久记忆。服务重启可读取已完成快照，不自动恢复执行、不重放业务写入。前端执行过程显示本轮上下文接续和整理状态，未提供长期记忆管理页面。

历史查询只取最近十个完成或等待确认的 run，排除失败、停止和中断轮次；仅回放用户输入与最终助手文字。上下文构建器对历史、任务数据和当前输入使用 12000 字符上限，优先保留当前输入和任务数据，按整条消息保留最近历史。不是 token 上限，也不包含系统提示、工具定义及本轮工具结果；现有执行次数、时间和 reported-token 预算继续有效。暂未做有损模型摘要，超出窗口的未结构化细节需重新询问。

`context` 事件记录消息保留数、省略数和字符预算；`context_update` 仅记录字段名与重置标记，不重复记录原文。当前短期快照沿用本机会话数据的保存周期，尚无自动过期/删除接口；不声称完成长期记忆治理。

## 验收场景与记录

自动化用合成数据覆盖：

| 场景 | 预期 |
| --- | --- |
| 政策补问使用情况，下一轮补充 | 检查器接收原任务和新原文，更新待补问项 |
| 用户更正已使用为没使用 | 原字段被新来源覆盖 |
| 切换订单 | 旧订单事实清除 |
| 重置任务 | 清空字段、待补问项和订单引用 |
| 伪造事实、授权字段 | 服务端拒绝 |
| 长对话 | 按预算省略较早消息，保留当前输入 |
| 新会话或不同账户 | 不读取其他任务快照 |
| 服务重启 | 已完成快照可用，不重放操作 |
| 停止、失败执行 | 不更新持久快照，不回放为成功历史 |

定向测试在 `services/agent/tests/test_task_context.py`。使用受控模型替身验证状态传播和分支，并不衡量真实模型字段抽取/指代准确率。完整回归用 `scripts/verify-p2.ps1`，结束后关闭显式 fixture，禁止付费模型自动验收。

后续真实模型评测应固定模型版本、温度、语料版本和多轮场景，分别运行“仅历史窗口”与“历史窗口加任务状态”。逐轮记录期望字段、实际字段、正确订单、是否重复补问、是否误操作、完成状态、token 和端到端耗时。按场景族分开开发集与人工复核的留出集；报告任务完成率、订单选择错误率、事实更正成功率和不必要补问率，不能把本轮固定测试的通过率当作真实模型指标。

本轮不宣称完成强制政策意图路由、逐句蕴含验证、自动断点恢复、完整工具结果压缩或长期偏好记忆。这些应独立设计与验收。
