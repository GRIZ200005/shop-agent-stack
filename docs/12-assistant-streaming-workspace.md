# 助手工作区与流式回答

> 阶段记录：保留当时的方案、结果与限制，不代表当前全部状态。安装和当前能力以[工程文档首页](README.md)为准；后续更新不改写此处原始实验结论。

更新：2026-09-15。

## 用户体验

- 助手占满主工作区，移除宣传标题、大块外边距和外围卡片。历史对话位于左侧，手机端转为横向对话栏。
- 对话内容独立滚动，输入框固定在工作区底部。用户向上阅读时不强制跟随新内容。
- 正文采用深色 16px 字体，支持 Markdown 加粗、列表、表格、引用和代码。禁用原始 HTML、远程图片渲染，链接使用安全 URL 转换与新窗口隔离。
- 折叠“执行过程”展示工具名称和完成状态。正文单独呈现；订单与售后卡片按各自 ID 合并，避免列表查询和详情查询重复展示同一订单。
- 不显示或持久化模型原始内部推理。仅在供应商协议需要时，将 `reasoning_content` 保留于当前运行内存，供工具调用往返使用。
- 提示模型先回答结论，再列必要明细；订单状态展示中文含义。模型是否遵循表达要求仍需真实模型验收。

## 链路

浏览器发送请求 → LangGraph 运行 → 供应商 Chat Completions SSE → `assistant_delta` 持久事件 → 已有鉴权 SSE → Markdown 增量渲染。

供应商请求设置 `stream=true`、`stream_options.include_usage=true`。首段正文立即推送，后续按字符量或接收时的时间间隔批量记录，避免逐 token 写 SQLite。最终 `assistant` 与分段事件使用同一 `message_id`，前端用完整回答替换累计文本，刷新恢复也不会重复。旧事件没有该字段时仍能显示。

供应商流中的工具调用按索引拼接 ID、函数名和参数，完整正常结束后才进入现有工具白名单与预算校验。网络中断、输出长度截断、错误结束不视为成功，收到的正文保留并标记未完成。没有自动重试或静默回退到非流式/测试引擎。

设置页显式“测试已保存连接”仍使用短的非流式请求。自定义服务需支持上述兼容 SSE 协议，否则给出失败提示。原有账户隔离、加密密钥、固定公网地址连接、售后预览与确认提交边界保持不变。

## 验证记录

- 前端生产构建通过，同时收集 106 个运行依赖的随包许可证。
- 完整 P2 验收：Python 35 项通过、1 项跳过；浏览器 8 项通过；原有 API smoke 17 项与退款数据一致性检查通过。
- 新增流式传输测试覆盖四类服务商请求格式、跨网络片段的中文字符、正文提前到达、工具参数拼接、usage、截断失败、推理不进入前端事件、最终回答与增量一致。
- 浏览器专项覆盖逐段 Markdown 显示、过程折叠、订单去重、刷新恢复，以及 1920px / 390px 布局与底部输入框；完成视觉检查。
- 首段即时推送修正后，流式与运行时 10 项专项及聊天浏览器专项再次通过。
- 测试使用 HTTP 模拟流或显式非 AI 测试引擎、合成账户；没有读取用户密钥或发起真实付费模型请求。正常使用环境恢复为禁用测试引擎。

真实模型的首字延迟、输出速度、推理耗时和结论质量尚未在本轮量化；供应商可能先在内部推理，因此发起请求与看到首段正文之间仍可能有等待。已有会话能显示新排版，但只有新发起的回复会使用新流式链路。
