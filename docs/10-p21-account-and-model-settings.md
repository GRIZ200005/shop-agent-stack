# P2.1：登录、账户与个人模型设置

> 阶段记录：保留当时的方案、结果与限制，不代表当前全部状态。安装和当前能力以[工程文档首页](README.md)为准；后续更新不改写此处原始实验结论。

日期：2026-09-15。该文档更新 P2 的登录和配置方式；真实模型效果测试仍暂停。

## 使用方式

1. 打开 http://127.0.0.1:18030/login ，登录或创建客户账户。未登录访问商城、订单、助手或工作台会先进入登录页，验证登录态后才显示工作区。
2. 登录后，点击左下角头像/昵称，打开个人设置或模型设置，也可以切换账户、退出登录。
3. 模型设置选择 DeepSeek、OpenAI、Kimi 后，从下拉框选择模型，再填写个人 API Key（官方地址已预填）。自定义接口保留模型标识手填，点击保存即可生效，无需编辑 `.env` 或重启服务。列表及更新规则见 [模型选择说明](11-model-selection.md)。
4. 已保存密钥只显示固定掩码，输入框留空表示保留；输入新值表示替换。修改基础地址时必须重新输入密钥，避免把旧密钥意外发送到另一个服务商。
5. “测试已保存连接”对保存的配置发起短请求，可能产生少量 API 费用；只验证基础响应，实际工具能力仍需后续对话验收。本轮自动化不会调用真实服务商。
6. 在个人资料设置显示名称、默认模型和紧凑界面。打开助手时自动采用本人可用的默认模型。

客服和管理员也使用独立登录页与账户菜单，但本轮不提供员工个人模型凭据或平台配置控制台；平台配置仍可由部署端初始化。此版本不是多租户 SaaS。

## 隔离与密钥管理

- 个人资料与模型配置使用经过 Java 登录态认证的 member ID，客户端不能指定其他用户身份。每个账户、每个供应商各一份配置；个人配置优先于已有平台配置。
- 使用已锁定 cryptography 的 Fernet 认证加密，将模型配置保存到 Agent 的 SQLite 数据卷。密文绑定账户和供应商，不能通过搬移记录串号。Java 仍负责订单、售后等 MySQL 业务数据。
- 部署密钥由启动脚本首次自动生成在被忽略的 `.local/agent-encryption.key`，以只读文件挂载到 Agent；不与业务 SQLite 文件放在同一个数据卷。不提供浏览器管理该部署密钥的入口。
- 备份/迁移需同时保留 Agent 数据卷和这份部署密钥。密钥遗失将无法解密已有配置；不要删除或随意重新生成。当前未实现在线轮换。加密不能抵御已控制应用进程或同时取得部署密钥的攻击者。
- API 返回固定掩码及是否已保存，不返回原始密钥；不写浏览器 localStorage/sessionStorage，不把验证错误中的输入或服务商错误正文回显。运行使用内存中的配置快照，不把密钥记录在 run/event 中。
- 自定义出站仅允许 HTTPS、443、公网地址，无凭据/查询参数 URL；每次连接解析 DNS 并拒绝非公网 IP，固定已检查的 IP 建连，保留原域名的 TLS SNI/证书验证。关闭重定向和环境代理自动继承。此阶段不支持本机 HTTP 模型服务。
- 修改/删除配置不影响已经开始的模型请求；新执行读取新配置。切换或退出会清理当前标签页的 Aster 登录态及会话选择，其他标签页不自动退出，已有 JWT 尚无服务端撤销机制。
- 客户身份接口已限制到 id、username、nickName，不再返回会员实体中的密码哈希等字段。

加密和出站实现参考 [cryptography Fernet 文档](https://cryptography.io/en/latest/fernet/) 与 [HTTPX 自定义传输文档](https://www.python-httpx.org/advanced/transports/)，未复制私有工程代码或元数据。

## 启动与验证

```powershell
# 已有构建时正常启动；首次使用会创建部署密钥
./scripts/start-p2.ps1

# 源码更新后构建并启动
./scripts/start-p2.ps1 -Build

# 只运行本地工程验收，最后恢复普通模式
./scripts/verify-p2.ps1
```

新增 Python 检查覆盖加密后无明文、账户/密文绑定、密钥保留替换删除、默认配置、公网 URL 和 DNS 固定、API 鉴权与验证错误脱敏。浏览器新增登录跳转、错误密码、配置保存不回显、刷新恢复、默认模型、账户切换隔离、手机端菜单场景；原 P1/P2 用例已按独立登录流程调整，保留业务断言。

本机验收通过：Java 定向测试 12 项；Python 28 项通过、1 项真实模型 smoke 跳过；浏览器 6 个场景（原 P1/P2 五个和新增账户设置场景）；API smoke 17 项与 MySQL 售后状态核对通过。另验证了个人配置确实传入对应账户的运行，同时不进入 run/event 记录。

连接测试按钮的错误展示使用 HTTP mock 验证，不发送合成密钥到外部。真实供应商连通性、费用与效果不在本轮验收结论内。截图与报告保存在 `.local`，不自动发布。最终服务恢复普通模式，规则测试引擎关闭；公开文件扫描未发现本机凭据或部署加密密钥。
