## 首次完成的实验

## 技术选择

使用独立 Docker Compose 的 Milvus 2.6.15、etcd 和 MinIO。版本取自本机已有镜像并固定，不追随 latest；Milvus 主机端口仅绑定 127.0.0.1:19530，MinIO 与 etcd 不发布主机端口。该实例用于本地开发，使用其默认内部认证配置，不是可直接暴露公网的部署。

第一组嵌入模型采用 BAAI/bge-small-zh-v1.5，精排采用 BAAI/bge-reranker-base，均在 CPU 本地运行，不调用付费模型。模型为中文资源成本基线，不宣称它们是当前最强模型。下载固定提交的 safetensors，禁用 trust_remote_code，权重保存在 Docker 模型卷，不进入 Git。模型标识、revision、库版本记录在每次实验的清单。

BM25 保留现有中文二元组实现。Milvus 存放 240 条客户草案的嵌入，先用 COSINE + FLAT 精确向量搜索，避免将近似索引误差混进首次对照。扩大语料后再独立比较 HNSW 的召回和延迟。本轮集合是独立实验集合，不包含内部 SOP、订单或个人数据。

RRF 计算每条候选在各路排名的 `1 / (60 + rank)` 之和，相同证据按条款 ID 去重；不直接相加 BM25 和向量分数。Rerank 使用问题与候选正文做交叉编码评分，是另一项模型计算，不等于 RRF。

## 六组对照

| 名称 | 候选来源 | 最终排序 |
|---|---|---|
| bm25 | 关键词 top 20 | 原排序取 5 |
| dense | Milvus 向量 top 20 | 原排序取 5 |
| rrf | 两路各 20，RRF 合并保留 20 | 取 5 |
| bm25_rerank | 与 bm25 相同的候选 | 精排后取 5 |
| dense_rerank | 与 dense 相同的候选 | 精排后取 5 |
| rrf_rerank | 与 rrf 相同的候选 | 精排后取 5 |

候选上限一致，便于分别观察候选召回和精排的影响。RRF 合并池最多 40 条，本轮只精排融合后的前 20；这是一项明确实验参数，不保证最优。后续调整候选池时必须保留旧配置、另开运行记录。

## 自动化运行与记录

在项目根目录运行 `./scripts/evaluate-retrieval.ps1 -Build`。后续运行省略 -Build；默认 3 轮，`-Repeats 1` 用于快速检查，不是稳定延迟结论。

每次创建 `.local/retrieval-runs/<UTC时间_唯一后缀>/`，不会覆盖旧结果：

`services/retrieval/requirements.lock` 固定完整已安装依赖，配置中的 model_revisions 固定权重提交。跨次比较可运行 `node scripts/compare-retrieval-runs.mjs <旧运行目录> <新运行目录>`；语料、题集或候选预算不同会拒绝当作同条件比较。

- `manifest.json`：RUNNING/COMPLETED/FAILED、实际配置、语料与题集哈希、实现代码哈希、模型 revision、依赖版本、Milvus 版本、索引参数、建库与模型加载耗时。
- `cases.jsonl`：每题每轮每方案的候选、最终证据、原始分数、各阶段耗时与金标命中。逐题写入，失败时已完成的记录仍保留。
- `summary.json` / `summary.csv`：Recall@5、MRR@5、二值相关性 nDCG@5、全标注证据覆盖率、p50/p95，并按单主题/多条款分类。
- `failures.json`：第一轮未召回全部标注证据的题目，用于检查漏召回、排序问题或等价证据漏标，不自动修改金标。

每次预热后按固定种子打乱问题，重复 3 轮。每题各基础组件实际执行，组合方案延迟使用串行组件耗时之和；p95 是这批 CPU 实验工作负载下的估计，**不是线上并发请求 p95**。模型冷启动和建库时间单独记录。未做置信区间或统计显著性检验，不凭小差值宣称确定优势。

72 个场景中 60 个可回答场景计检索分，12 个无答案/越权/注入场景只记录候选，行为状态为 NOT_RUN。后者仍需真实权限、答案与拒答验收，不能因脚本执行成功而算通过。当前题集已被观察且有等价证据漏标风险，只用于开发，不作为独立盲测。

完整比较须先确认语料、金标、切分规则、top-k 和硬件一致。改模型或代码时保留清单，用同题逐项差值分析；新增语料和新增题集需要建立新基线。下一步可将稳定测试环境的结果汇总到 CI，但暂不把不稳定 CPU 耗时设置为硬失败阈值。

## 在线接入边界

本轮首先建立可运行的检索对照，不直接切换客户助手：在线仍从 MySQL 权威目录执行原 BM25。实验数据源是离线编写包，不是线上增量同步的替代品。

上线 Hybrid 前须实现发布事件驱动的幂等索引更新、模型/索引版本、构建失败重试和原子切换，并保留当前版本、可见性过滤及最终来源哈希校验。政策撤回后不能等待向量索引最终同步才停止回答。精排结果不能越过权限或 Java 业务校验。

本轮实验结束删除自己创建的临时 Milvus 集合；Docker 卷、模型缓存与其他集合不删除。运行中断时清单可能停在 RUNNING，应按该清单中的具体集合名核实，不清空实例。
