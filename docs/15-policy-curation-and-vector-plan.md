## 一套可执行的模拟服务政策

按订单、模拟支付、配送、取消、退换申请、模拟退款、商品说明、账户与客服整理统一目录。客户政策与内部处理 SOP 分开授权；相同规则保持一致，避免为增加数量重复改写。

每份正式文档明确适用范围、条件、操作入口、处理结果、例外、版本和生效时间。逐条对照 Java 已实现的行为：未实现的能力不得写成当前承诺；真实资金、外部物流等能力明确属于模拟范围。系统能力不足时选择修正政策或先实现业务，再发布。

实施顺序：审阅草案与业务状态机 → 合并冲突和重复 → 准备条款级问题、证据和无答案场景 → 经管理员发布 → 客户页面、检索与引用回归。尚未实现的版本按历史订单适用规则也需单独设计。

## Milvus 方案（计划，尚未部署）

下一阶段采用 Docker Milvus Standalone，安装时核实机器内存、磁盘和兼容性，固定版本及镜像。官方 Compose 方案包含 Milvus、etcd、MinIO；本轮不新增这些服务。

- MySQL 保存政策正文、版本、权限、生效状态及发布记录，是权威来源。
- Milvus 保存可重建的条款向量和 policy_id、version、clause_no、hash 等定位信息；不是业务数据库替代品。
- 中文嵌入模型生成向量，与 BM25 检索结果融合，再评估重排是否值得引入。
- 发布通过事务事件记录驱动幂等索引同步；失败可重试，索引状态可观察。索引版本和嵌入模型版本需记录，支持重建和切换。
- 撤回、替代与权限过滤同时约束召回和最终来源校验。不能因为向量索引尚未同步就返回失效政策。

先保留 BM25 对照；同一语料、同一固定题集比较 BM25、Dense、Hybrid、Hybrid+Rerank 的 Recall@5、MRR、p50/p95 检索耗时、构建成本。另测无答案识别、过期/内部资料泄漏及回答引用支持率。开发集用于调试，独立验证集按场景族隔离；现有 24 题不能充当新的盲测集。全文答案的语义正确性另行人工抽查，不以检索命中率代替。
