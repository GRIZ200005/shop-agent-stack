## 数据与来源

| 数据 | 编写源 | 规模与边界 |
|---|---|---|
| 商品 | `catalog/products.tsv` | 100 件原创合成商品、10 类、100 张独立配图；另有 4 件基础商品 |
| 政策 | `knowledge/catalog-v2.json` | 96 份、288 条；80 份客户政策、16 份员工 SOP；另有基础政策 |
| 用户、订单、售后 | 测试自行创建 | 仅合成数据，不代表真实用户或成交规模 |
| 检索与对话题集 | `evaluation/` | 开发与预留场景分开；题目不进入知识索引 |

图片生成来源保存在 `catalog/image-manifest.json`。政策发布必须经过显式导入或管理员操作，员工材料不得作为客户检索证据。

## 测试入口

以下命令在仓库根目录、已准备依赖和合成目录的测试环境执行。它们会创建账号、订单和政策，应使用专门的测试数据库，不要对展示或其他有用数据直接运行。

| 范围 | 命令 | 说明 |
|---|---|---|
| Java 构建与领域回归 | `pwsh -File scripts/build-p0.ps1` | 干净构建、事务、库存、权限与订单归属 |
| 前端构建 | `npm --prefix apps/web run build` | TypeScript 与 Vite |
| 前端单元测试 | `npm --prefix apps/web run test:unit` | 时间格式与偏移 |
| 完整 MCP / 浏览器 / 业务验证 | `pwsh -File scripts/verify-p2.ps1` | 显式启用确定性测试模型，结束时恢复普通模式；不调用外部模型 |
| 在线检索及故障恢复 | `pwsh -File scripts/verify-p3c.ps1` | 包含 Milvus 停止与恢复，必须单独运行 |
| 退款故障验证 | `pwsh -File scripts/verify-p4.ps1` | 包含消息队列和消费者故障，必须单独运行 |
| 离线检索比较 | `pwsh -File scripts/evaluate-retrieval.ps1` | 按固定数据和模型比较检索方法，不等同于回答质量 |

## 环境隔离

测试使用独立的 Compose 项目、数据库和数据卷，避免污染展示账号、订单与会话。依赖和公开模型权重可以复用缓存；凭据及运行输出保存在 Git 忽略的本机目录。

依赖确定性模型的 Playwright 用例通过测试脚本启用相应配置。Milvus、消息队列与消费者的故障测试顺序执行，并在结束后恢复服务。真实模型测试单独配置提供商、题集和调用预算。

## 指标定义

| 指标 | 用途与解释 |
|---|---|
| 通过、失败、跳过 | 描述测试用例执行状态；契约测试检查权限、工具、状态和引用约束 |
| Recall@k | 衡量相关条款在前 k 个检索结果中的覆盖情况 |
| MRR@k | 衡量首个相关条款的排名 |
| nDCG@k | 衡量检索排序与相关性标签的一致程度 |
| 回答质量 | 单独评估答案正确性、引用支持程度与证据缺口处理 |
| 延迟与吞吐 | 结合数据规模、并发、时长、预热、错误率和资源配置解释 |

检索指标不等于答案准确率，确定性模型测试不代表真实模型表现。性能测试针对指定环境，不能直接外推为生产容量。
