# 数据、测试与指标口径

[文档首页](README.md) · [固定验收](records/34-v1-acceptance.md)

## 数据来源

| 内容 | 来源与规模 | 边界 |
|---|---|---|
| 商品 | 原创合成扩展目录100件、10类、100张AI配图；另有基础seed | 非商家真实库存，参数不是实物认证 |
| 政策 | `knowledge/catalog-v2.json`定义96份、288条；80份客户政策、16份员工SOP | 草案不自动上线；员工材料不进入客户检索 |
| 用户/订单/咨询 | 本机测试创建的合成数据 | 不是客户规模或真实交易数据 |
| 题集 | 人工编写的开发/预留场景与版本化标签 | 已观察的题集不算独立盲测；未运行数据不计通过 |

当前部署数量可能高于编写源（例如基础政策、修订记录和测试数据）；报告必须写明是源文件规模还是某次数据库快照。数据标记、图片哈希和导入记录见 [catalog](../catalog)、[knowledge](../knowledge/README.md)。

## 分层验证

| 层次 | 入口 | 副作用/解释 |
|---|---|---|
| Java聚焦回归 | `scripts/build-p0.ps1` | 构建且暂时停止应用；单元/事务测试不证明生产吞吐量 |
| 固定浏览器/API业务验收 | `apps/web` 下 `npm run test:v1` | 使用本机数据库，新增合成用户/订单/事件，部分模拟支付会消耗合成库存 |
| MCP真实集成 | 文档34的Docker命令 | 真实MCP→Java→MySQL，不调用模型；检索检查使用实际本机Milvus |
| 聊天界面/模型选择 | 固定验收中的对应spec | 使用Mock事件；不能作为真实回答正确率 |
| 离线检索比较 | `scripts/evaluate-retrieval.ps1` | 启动独立实验；有CPU/内存成本，不是每次提交必跑 |
| 真实模型开发实验 | 文档23、29、30中的显式live入口 | 可能计费；需要单独选择账户、预算与题集 |
| 故障/性能实验 | 文档25、27及对应脚本 | 单独运行，不与普通验收或并发实验混跑 |

不要直接把`npm run test:e2e`当作普通环境的一键入口：全量历史测试中有需要明确TestMode的用例。默认固定集合用`test:v1`；`verify-p2.ps1`会切换测试模式并运行更广集合，读清脚本再使用。

| 记录 | 实测摘要 | 不可推出的结论 |

报告的代码版本、数据、模型、硬件/网络条件和样本数都影响解释。旧实验数字不自动成为当前版本指标。

## 指标怎么读

- **Recall@k / MRR@k / nDCG@k**：衡量给定标签下的检索表现，不衡量完整答案正确性。
- **契约通过率**：工具、权限、状态、引用等自动约束是否满足；缺少人工审核时`answer_accuracy`保持未知。
- **任务完成率**：必须定义成功终态、分母、失败和未完成处理方式，不仅统计产生回答的次数。
- **延迟/吞吐量**：说明并发方式、持续时间、数据量、预热、错误计入方式和资源；离线CPU检索耗时不能代替在线接口P95。
- **tokens/成本**：区分提供商reported tokens、估计值和实际账单；配置阈值不是严格账单上限。

## 结果保存与发布

运行报告保存在`.local/`、`evaluation/runs/`等忽略目录。保留首轮失败和定向重跑，不覆盖或删掉失败后只发布成功摘要。发布时摘取核对后的聚合结果，标明对应日期/版本；原始会话、请求、账号和本机路径不直接上传。

新增功能只补关键风险的测试。默认验证范围保持有界；遇到新缺陷再增加有意义的回归。全新环境复现、独立人工答案审核和稳态容量验证仍是不同的后续工作。
