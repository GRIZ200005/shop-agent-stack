# 星序服务政策库 V2：内容与开发评测

> 阶段记录：保留当时的方案、结果与限制，不代表当前全部状态。安装和当前能力以[工程文档首页](README.md)为准；后续更新不改写此处原始实验结论。

后续状态：用户已授权在当前本地模拟环境发布本批内容，发布与在线验收见 [本地发布记录](17-policy-library-local-release.md)。下文保留编写阶段的离线评测记录；编写包默认状态与实例发布状态分别管理。

## 交付范围

2026-09-15 编写。96 份文档、288 条条款，包括 80 份客户政策与指引及 16 份内部处理规范。标题使用“星序商城售后申请资格说明”等稳定名称，POL/SOP 编号仅用于管理和证据追踪，不添加随机字符。

客户内容覆盖订单、支付、退货、退款、物流、商品、账户、客服、知识来源九类。内部规范覆盖领取、核对、审核、退款执行、重复请求、资料保护、政策版本与评测运营。内部资料不进入客户离线索引。

本批属于原创模拟业务资料，状态为 AI 辅助编写、待人工审核、未发布。正式命名不表示来自真实商家，也不表示已经成为对外承诺。本轮完成文件与评测，未修改线上政策和客户数据、未调用真实模型。

## 内容与业务的核对依据

| 当前实现依据 | 本批对应内容 |
|---|---|
| AfterSaleService.submit：订单归属、状态 1–3、正实付金额、已有申请复用 | 申请资格、整单金额、重复申请、零元边界 |
| AfterSaleService.claim/decide：领取人限制、审核说明、REFUNDED/REJECTED 与订单关闭 | 内部领取审核规范、客户状态说明与模拟退款结果 |
| AgentOperationService：预览有效期、确认、执行时金额重查、取消预览 | 预览、确认归属、金额变化和提交后的取消边界 |
| PolicyService：CUSTOMER/STAFF、发布、修订替代、撤回、条款哈希 | 发布与受众规范、失效引用与历史回答说明 |
| 现有助手工具范围及 P2/P3a 文档 | 不承诺自动换货、补发、真实物流、实时人工转接或真实支付 |

这是代码对照，不是对全部自然语言承诺的人工审核或法律审查。发货、保修、赔偿等场景用于明确缺少何种证据，不虚构固定天数、金额或仓库地址。未来接入真实履约时应修订这些条款，并建立对应验收。

旧 48 份内容按原编号保留，标题统一为正式名称；新增 32 份客户资料和 16 份内部规范。相邻规则之间存在必要交叉引用语义，例如退款状态与退款凭证；未通过随机换词复制条款扩大数量。仍需人工合并可精简的主题，数量不是质量目标。

## 文件与复现

- `knowledge/authoring/policies.tsv`：唯一当前客户内容源。
- `knowledge/authoring/staff-policies.tsv`：内部内容源，不能用客户默认可见性导入。
- `knowledge/handbooks/customer.md`、`staff.md`：可阅读目录和全文。
- `knowledge/catalog-v2.json`：受众、待审状态、稳定条款 ID 与哈希。
- `knowledge/archive/v1`：旧原文、哈希清单和题集，不纳入当前索引。
- `evaluation/policy-scenarios-v2.tsv`：72 个场景及证据、预期行为，独立于内容源。
- `evaluation/reports/policy-scenarios-v2-bm25.json`：每题候选与得分，可逐项检查失败。

先运行 `node scripts/build-policy-handbook.mjs`，验证编号、标题、逐字重复条款和金标引用；再按 knowledge/README.md 的 Docker 命令运行两套离线评测。结构检查不判断所有语义重复和规则冲突。

## 实际评测结果

80 份客户资料、240 条证据，BM25 中文二元组、top 5。未使用向量、重排或模型生成答案。

| 新开发集 | 题数 | 条款宏平均 Recall@5 | MRR@5 |
|---|---:|---:|---:|
| 单主题可回答题 | 48 | 77.08% | 0.6736 |
| 多条款题 | 12 | 47.22% | 0.4931 |
| 合计 | 60 | 71.11% | 0.6375 |

另外 12 个信息不足、越权、恶意指令场景已编写预期行为，尚未运行模型或线上权限验收。脚本只保存检索候选，不把这些题计为通过，不要求无答案问题一定没有相关候选。

旧 24 题在扩充后客户库上 Recall@5 仍为 85.42%。旧题和新题难度、数量及标签不同，不能将 85.42% 与 71.11% 直接解释为同一系统退化。完整语料和金标哈希见各报告。

## 能证明什么，不能证明什么

这些资料可以作为真实执行的离线检索实验与端到端验收的业务背景。真实评测的关键是运行真实检索、保留可追溯结果、按预先定义的标准判断，而不是要求每份资料都抄自外部商家。

但是当前语料和题目由 AI 辅助共同编写，属于已观察开发集，不能证明真实用户分布下的泛化能力。高分也不能证明回答符合证据或订单操作安全。

金标目前是“已标注相关条款集合”，存在等价证据漏标风险；如 E047 两条相关条款支持同一结论，不代表答案必须引用两条。报告中的全标注证据覆盖率仅为检索诊断，不能等同答案合格率。人工复核应记录等价证据、必须联合使用的证据以及标签修订理由，不按当前检索结果反向挑金标。

后续在固定库上比较 BM25、Dense、Hybrid 和重排，另测回答事实正确、引用支持、证据不足时补问、越权泄漏与任务完成。独立验证集应由未参与编写的人按场景族制作并冻结，不把当前题目同义改写后冒充盲测。扩充真实用户脱敏问法需另行确认来源与使用授权。

## 发布前的内容工作

人工通读两本手册，确认服务承诺与页面功能匹配；将客户资料按主题整理后通过管理员发布，内部资料明确设为 STAFF。发布后建立文件条款 ID 到数据库政策 ID、版本、条款号的映射，再用线上检索复验；不能直接把离线 POL 编号当作数据库主键或引用 ID。

在线客户和管理员列表当前只显示最近 100 条，管理员历史草稿加上新库可能超过此上限。批量导入前应补管理列表分页或按明确 ID 跟踪导入状态；不能因某条不在第一页就重复创建。独立检索目录已有游标分页，不受这个列表上限影响。
