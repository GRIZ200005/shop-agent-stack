# 实施与学习路线

目标：完成 01 文档定义的 v1.0。当前 P0 后端基线和 P1 首个三侧业务闭环已通过本机验证，当前运行方法与证据见 08 文档。阶段门槛优先于固定周数，外部账户条件单独追踪。

## P0：可复现基线

交付：固定 mall 提交和许可证、运行环境清单、Compose profiles、数据库迁移方式、最小健康检查、upstream 与自研贡献边界。

动作：验证 JDK/数据库版本、启动上游必要模块、配置独立测试凭据；确定 Python Agent/MCP 是同进程还是独立服务。先让公开底座完成登录、查询与一笔测试订单。保留旧学习项目基线，不原地改坏。

门槛：在干净环境按文档启动；不需要内部企业服务。尚未启动成功时不进入大量功能生成。

学习：HTTP、Spring 项目结构、配置、SQL、日志与 Docker。

## P1：三侧 UI 与非 AI 闭环

当前交付：已实现 React 三侧页面、真实商品/购物袋/订单、售后申请、原子领取、审核/拒绝、同步模拟退款、账号角色创建与政策草稿发布。浏览器三角色闭环通过。当前人工接管指售后工单归客服处理；Agent 接管协调尚待 P2。详细范围和边界见 08，不将本轮视为整个 v1.0 完成。

交付：React 设计 tokens、布局、登录、客户商品/订单、售后申请、客服队列/审核、管理员权限与基础政策管理；Java 售后状态机与渠道模拟器。

先完成一个真实垂直切片：客户提交 -> 客服审核 -> 模拟退款 -> 客户看到结果。UI 可以分阶段变精致，但不能用固定数组替代最终业务接口。

门槛：三角色 E2E 通过；客户不能看他人订单；客服接管和领取可验证；无需 AI 可完成流程。界面涵盖空态、加载、错误、权限不足和移动端抽屉。

学习：Java 集合/异常、Spring MVC/DI/事务、MyBatis、索引和认证授权。独立写一个受权限保护的修改接口。

## P2：Agent 运行基础与业务 MCP

交付：Python 会话/run 分层、事件协议、短期授权上下文、常驻 MCP、工具 schema、确认卡、停止与恢复语义。

先做一个只读订单工具与一个售后提交工具，MCP 适配复用 Java 业务接口。HTTP 契约可先开发验证，但阶段完成必须经过真实 MCP SDK 流程。

门槛：模型不能指定任意用户身份；确认凭据只能消费一次；标准 MCP 发现/调用测试通过；前端 run_id/operation_id 可关联；重放答复不重复提交。

学习：工具调用、schema、鉴权、幂等键、SSE/事件模型、超时。

## P3：Agentic RAG 与网络搜索

交付：政策发布与索引、版本/可见性过滤、Hybrid 检索、充分性检查、改写重查/补问/拒答分支、受控网络 provider。

门槛：真实复现“第一次证据不足，补查后回答”的场景；预算耗尽会停止；本店政策缺失不拿外店条款替代；网络查询不含客户私人字段；完成真实 provider smoke，固定快照回归通过。

若无可用搜索凭据，完成其他工作并明确该项未验收；不能把 mock 当作真实联网。

学习：召回与重排、状态图、检索金标、token 成本、网页来源与缓存。

## P4：可靠执行与前端恢复

交付：Outbox/RabbitMQ、退款 worker、幂等约束、待核实查询、重试/对账、同会话并发控制；快照+事件游标恢复；长会话渲染和真实业务卡片。

门槛：成功后响应丢失、重复消息、回调乱序、进程重启、客服并发审核都能按预期收敛；SSE 重连不丢失/重复最终消息；中止 Agent 不伪装成退款撤销。

学习：事务隔离、锁/CAS、线程池、MQ 投递语义、缓存一致性。独立复现并修复一个竞争条件。

## P5：评测、性能与作品交付

交付：360 场景族目标集、评分器反例、固定 holdout、三档数据、消融、k6 与浏览器报告、贡献清单、操作视频、恢复手册。

门槛：达到 03 文档门槛或如实列出不足并继续修复；在另一干净环境复现；3–5 位试用者完成客户/客服任务，记录失败点和修复，不把少量试用写成规模上线。

学习：执行计划、profile、统计口径、系统设计和面试表达。脱离 AI 提示，从页面动作追到数据库结果。

## 可选 v1.1

第三方电商 MCP、更多品牌公开数据、邮件渠道、SLA 自动升级或多租户选其一推进；前提是 v1.0 证据完整。外部平台写操作需要独立授权、资质与验证，不因自建 MCP 可用而自动视为已打通。

多 Agent 只有在明确独立任务与评测收益时再加；不把子 Agent 数量作为架构先进程度。

## 学习原则

采用小闭环后边做边学：约 60% 实现、25% 原理、15% 独立复现作为初始时间分配。P1 就开始学，而不是等整个系统生成完成。

架构图是地图，关键代码决定事实。应能独立解释：请求身份从哪里来、事务何时提交、两次并发会怎样、失败后谁恢复、每项指标如何计算。业务核心代码必须读懂，第三方框架内部可按问题深入。

面试基础通过项目关联：退款对应幂等与消息可靠性；订单竞争对应锁与事务；查询变慢对应索引和执行计划；SSE 对应 HTTP 与连接；Agent 成本对应预算和缓存。Java/JVM、网络、操作系统和算法另做持续练习，不能仅靠项目框架图替代。

## 完成后应存在的材料

本项目所有公开文件和截图不包含企业内部标识、接口、密钥、专有材料或真实客户数据。发布前检查的是实际内容，而非只改产品名。
