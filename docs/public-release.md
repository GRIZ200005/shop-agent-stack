## 交付内容

- 保留源代码、依赖锁文件、部署配置、迁移、合成数据和工程文档。
- 本机凭据、数据库、模型缓存、日志及测试输出不进入仓库。
- 展示素材使用合成业务数据，检查图片中的账号、联系方式与地址。
- 功能介绍与代码保持一致，明确模拟流程、部署边界和第三方来源。

## 发布流程

1. 按安装指南构建并运行应用，检查迁移、数据导入、模型缓存与端口配置。
2. 在隔离环境执行对应回归测试，故障测试结束后恢复服务。
3. 检查跟踪文件及 Git 历史中的凭据、个人信息和第三方材料；发现凭据泄露时撤销或轮换凭据。
4. 核对许可证、依赖与分发资源，配置仓库可见性、默认分支及漏洞报告入口。
5. 发布与源码对应的版本，说明功能变化、兼容性和部署要求。

常用检查入口：

```powershell
git status --short
git ls-files
git log --all --name-only --format=
git remote -v
git check-ignore .env .local/p1-accounts.json .local/agent-encryption.key
```

文件列表检查需结合凭据扫描与素材审查；公开问题中仅提供必要的脱敏输出。共享历史重写需要协调协作者，避免覆盖其他人的提交。
