## 公开前清单

以下是需要实际执行和留下结果的检查，不是已经完成的认证。

- [ ] **全新环境复现**：独立目录/环境按安装手册运行，确认镜像、模型、迁移、导入和端口前提，不依赖开发机器已有卷。
- [ ] **当前跟踪文件**：检查源文件、图片、Office/PDF、压缩包、日志、截图和测试数据，排除凭据、私人数据和无权公开的材料。
- [ ] **完整Git历史与ref**：当前文件干净不代表旧提交/分支/tag干净；检查历史文件、提交作者和邮箱、删除过的配置、远程地址、二进制资源。
- [ ] **依赖与来源**：保留上游许可证/作者/修改说明；核对lockfile、镜像及模型revision，确认准备分发的资源范围。
- [ ] **演示素材**：只使用合成账号与业务；截图要检查所有可见区域，不能直接搬运本机历史报告。
- [ ] **结论与数字**：注明实验版本、样本、失败/复测、Mock与真实调用，不宣传未完成特性或生产指标。
- [ ] **仓库配置**：确认可见性、默认分支、许可证展示、Issue/PR流程和漏洞报告设置。配置是否已开启必须实查。
- [ ] **负责人复核**：确认后再修改GitHub可见性或发布Release。文档修改、本地commit不等于已经授权或完成公开发布。

## 初步自检命令

在仓库根目录执行；检查输出后再采取修改，不直接管道执行删除或历史重写。

```powershell
git status --short
git ls-files
git log --all --oneline
git log --all --format='%h %an <%ae>'
git log --all --name-only --format=
git remote -v
git check-ignore .env .local/p1-accounts.json .local/agent-encryption.key
```

这些命令只是审阅入口，不是secret scanner，也不证明没有泄露。不要将含敏感输出的完整扫描结果发到公开Issue。可另外用固定版本的凭据扫描工具覆盖所有历史，并人工检查误报、二进制和元数据；工具没有报警不能替代来源审查。

发现历史问题时，先确定授权与影响范围，必要时轮换凭据、移除不应分发材料，再协调历史重写与协作者同步。不要未经确认对共享分支force-push或“清空历史”来掩盖问题。
