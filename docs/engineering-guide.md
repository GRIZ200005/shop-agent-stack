# 原创贡献、代码阅读与学习路线

[文档首页](README.md) · [上游来源](../THIRD_PARTY_NOTICES.md)

## 项目定位

这个项目提供可运行的AI应用与后端业务链路，不是凭项目名称或组件数量证明工作经验。学习目标是能解释一次请求如何认证、读写数据、失败、重试并最终对用户可见，也能定位和修改关键代码。

## 来源与贡献

| 范围 | 来自哪里 | 本项目的主要变化 |
|---|---|---|
| 商品/会员/订单基础与schema | `macrozheng/mall`固定提交 | 保留来源；增加归属校验、价格/库存保护、部分旧入口限制等修改 |
| 三侧前端 | 原创Aster实现 | 登录/设置、聊天、业务卡片、咨询、商品管理与履约 |
| Agent与MCP | 原创集成与运行约束，使用公开依赖 | 身份授权、工具预算、确认边界、来源复核、任务上下文、SSE |
| 政策与检索 | 原创合成政策/编排，使用公开模型和数据库 | 版本化条款、发布Outbox、混合检索/精排、有界证据子图 |
| 可靠模拟退款 | 原创Aster业务模块 | Outbox、MQ、幂等消费、本地账本、重试与只读核对 |
| 交付工具 | 原创本机脚本和测试 | 分层验证、失败保留、数据导入、固定演示 |

“原创”表示本项目中的独立实现范围，不意味着没有使用AI开发工具、开源框架或上游基础。描述个人贡献应与实际参与和理解程度一致，不能直接把整张表当成已经掌握的技能清单。

## 建议阅读顺序

1. **一笔订单**：前端购物袋/结算 → Portal controller → Service → SQL → 事务。找出后端价格权威、地址归属、库存占用和回滚点。
2. **一次售后退款**：申请/领取/审批 → Outbox → MQ → 消费者 → 账本。解释重复投递、失败重试、人工核实和为何消息确认不是业务成功。
3. **一次Agent查询**：Web SSE → FastAPI → runtime → MCP → Java → MySQL。解释模型为什么拿不到任意用户身份，以及错误如何回到页面。
4. **一次政策更新**：发布/撤回 → 目录代际 → 索引worker → 混合检索 → 来源复核。区分数据库事实、检索候选和模型判断。
5. **一次跨角色操作**：人工咨询或发货 → 角色检查 → 行锁 → 幂等事件 → 页面刷新。手工构造错误请求并解释拒绝位置。

## 对应知识点

| 主题 | 在项目中练习 | 应能回答的问题 |
|---|---|---|
| REST与HTTP | 同源代理、登录、业务返回码、SSE | HTTP200为什么不一定表示业务成功？流式连接如何显示失败？ |
| Spring Boot | 配置、依赖注入、事务代理、校验 | 事务在哪一层？哪些异常会回滚？谁决定角色？ |
| MySQL | 外键/唯一约束思路、索引、行锁、条件更新 | 并发占用为何不能先读后覆盖？查询计划证明了什么？ |
| Redis | 上游缓存/验证码/序列用途 | 缓存与业务权威如何区分？没有实现的缓存优化如何避免夸大？ |
| RabbitMQ | 投递确认、重试、重复消费 | 如何在消息重复时保证业务结果只落一次？ |
| Agent/RAG | 上下文预算、工具协议、证据与引用 | 来源哈希一致为什么仍不保证语义正确？记忆为何不能保存价格当权威？ |
| TypeScript/React | 异步请求、状态、表单、对话框、SSE | 旧请求如何避免覆盖新状态？为什么重复提交要后端保护？ |
| 测试/交付 | 合成夹具、集成测试、版本化结果 | Mock通过说明什么？哪些证据不足以写进简历？ |

不必把框架每个源码文件背下来，但必须看懂你讲到的关键实现。理解架构和阅读代码是互相验证的关系；基础题可围绕实际请求、事务、锁、索引和网络机制学习，不用二选一。

如果填写具体数字，链接[测试证据](testing.md)并说明数据规模与实验条件。不要写“自研完整电商底座”“答案准确率100%”“生产千级QPS”“真实资金退款”或“已具备企业高可用”，除非后来有独立可复核的证据。

## V1之后的优先级

**先做**：在隔离的新环境执行部署手册、记录阻断；完成主要链路的代码阅读与故障解释；公开前完成历史/资源检查。

**按具体需求再做**：补全普通用户取消订单等业务缺口；商品元数据服务端标准化；通知、附件、多包裹；更大数据规模下的SQL/缓存实验；长期记忆或商品语义检索；容器安全、备份恢复及多实例设计。

**不作为当前学习前置条件**：真实支付、外部商家接入、多租户大平台、自动扩容或不断增加评测矩阵。是否能投某类岗位还取决于基础、编码、调试与解释能力，项目完成本身不是能力认证。
