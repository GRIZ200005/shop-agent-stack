2026-09-15，用户要求开始内容审核后分批上线的下一步。本轮在本地模拟商城发布 80 份客户政策（240 条）与 16 份内部规范（48 条）。未向 GitHub 提交或推送，未调用真实模型或外部支付渠道。

## 内容与状态

开发助手对照 AfterSaleService、AgentOperationService、PolicyService 和已实现的页面/工具范围核对内容；未将模拟退款写为真实到账，未新增固定配送、保修或赔偿承诺。这不等于独立人工内容审核或真实商业适用性审查。

原编写包与手册默认保留未自动发布的元数据；本实例通过管理员 API 完成发布，其版本与生效时间以 MySQL 为准。没有撤回、替换其他既有正常政策。因原先还有一份客户政策，验收时客户列表合计 81 份。

## 导入方式与恢复

`node scripts/import-policy-library.mjs` 默认仅验证编写资料、目录哈希与受众，不连接服务或修改数据库。

经授权使用 `node scripts/import-policy-library.mjs --publish` 在固定的 localhost:18030 发布。凭据从忽略目录读取，日志不输出凭据；仅用于当前本地开发环境。

脚本先分页读取既有政策，对所有同名冲突预检。仅复用标题、正文、受众完全一致且为草稿或已发布的记录；不自动覆盖修订、撤回或冲突记录。创建、发布分步记录映射，中断后可顺序重跑，回收已创建的同名草稿继续发布。每份文档发布后核对 3 条条款，生成文件条款到线上版本、条款号和引用 ID 的映射。

映射保存在忽略文件 `.local/policy-library-v2-import.json`，未把实例主键写入通用资料。重复执行实测 created=0、published=0、verified=96。该脚本不支持多个导入进程并发运行；当前没有服务端唯一外部编号约束或跨文档整批事务，冲突需人工核对，不能声称并发幂等或整批原子性。

## 页面与分页

政策列表接口增加 `before` 游标参数，保持每批 100 条和原数组响应。前端逐批加载，在已加载资料上关键词搜索，每页显示 10 份；管理统计覆盖完整已加载目录。超过 10,000 条明确报错，后续再升级为服务端搜索与统计。跨页读取不是事务快照，刷新可获取期间的最新发布变化。

客户只读取当前有效 CUSTOMER 政策；后台可查内部规范。引用原文仍按 policy ID 和 version 读取，来源校验不依赖列表页码。
